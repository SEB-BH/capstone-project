# Client Handoff Checklist

Use this checklist to prepare a professional final handoff. Adapt it to the project.

## Product access

- [ ] Final deployed/published URL(s) provided.
- [ ] Repository URL(s) provided or ownership/access transferred as agreed.
- [ ] Domain/hosting information documented where applicable.
- [ ] Administrative access instructions provided where applicable.

## Documentation

- [ ] Project overview and purpose documented.
- [ ] Setup/run instructions documented for technical projects.
- [ ] Main technologies/services documented.
- [ ] Important workflows or administrative tasks documented.
- [ ] Known issues and limitations documented.
- [ ] Recommended next steps/future enhancements documented.

## Accounts and credentials

- [ ] Client-owned accounts are used or ownership is transferred where appropriate.
- [ ] Required service/account information is listed without exposing secrets.
- [ ] Passwords, tokens, API keys, and secret credentials are transferred separately using an appropriate method.
- [ ] No secrets appear in public repositories, README files, Trello, or the handoff document.

## Data and assets

- [ ] Client-provided logos, images, content, and data are stored/returned appropriately.
- [ ] Any licensing or attribution requirements are documented.
- [ ] Backup/export information is provided where relevant.

## Maintenance

- [ ] Client understands any recurring hosting/service costs where applicable.
- [ ] Client understands what may need maintenance or updates.
- [ ] External dependencies/integrations that could break or change are noted.
